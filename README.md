# AutoFeatureRec: автоматическая генерация исторических признаков для рекомендаций

**[Полный исследовательский отчёт → REPORT.md](REPORT.md)**

## Исследовательский вопрос

Может ли автоматический перебор исторических агрегатов и их отбор по важности конкурировать с градиентным бустингом на заранее сконструированных признаках? Исследование сравнивает **CatBoost с ручными признаками** и **CatBoost с автоматически сформированными признаками** при одинаковом наборе кандидатов внутри запуска.

## Данные и постановка

Используется открытый [KION dataset](https://github.com/irsafilo/KION_DATASET). Из исходного набора случайно выбираются **15 000 пользователей**, для каждого сохраняются все доступные записи взаимодействий. В основном итоговом запуске `SEED=2026`: **84 358** записей, **5 798** объектов. Период данных: 13 марта — 22 августа 2021 года.

Для каждого временного среза ранжируются фильмы, присутствующие в историческом каталоге и ещё не просмотренные пользователем. Положительная метка — просмотр в следующем временном интервале. Для каждого положительного объекта выбирается до 15 отрицательных объектов из каталога, отсутствующих в истории и среди положительных объектов целевого интервала. Не более четырёх положительных кандидатов на пользователя/срез.

**Ограничение:** отрицательная метка означает отсутствие зарегистрированного просмотра в заданном интервале, а не показ без клика. Нельзя интерпретировать полученные метрики как оценку онлайн CTR. Кандидаты и множество оцениваемых пользователей зависят от будущих положительных взаимодействий, поэтому оценка условная и потенциально оптимистичная относительно реального потока рекомендаций.

## Временная схема и защита от утечек

Исторические признаки каждого среза считаются **только по записям `ts < cutoff`**. Два первых среза образуют train, третий — validation, четвёртый — test. Модели сравниваются на одних и тех же парах и метках внутри запуска. Отбор автоматического набора производится по **NDCG@10 на validation**. Test используется для итоговой оценки выбранной модели.

Важное ограничение источника: `last_watch_dt` — дата последнего просмотра, а `total_dur` и `watched_pct` — доступные агрегированные характеристики взаимодействия, не полноценный журнал отдельных событий. Следовательно, временная реконструкция неполна. Длительность и процент просмотра используются только из записей с датой раньше cutoff, но если исходные агрегаты были обновлены поздними просмотрами, этот источник не позволяет полностью исключить информационную утечку внутри записи. Выводы следует трактовать с этой оговоркой.

## Методы

- **Popularity:** историческое количество взаимодействий с объектом.
- **Manual:** CatBoost с 17 признаками (жанр и пользовательские/объектные/жанровые агрегаты на заранее выбранных окнах).
- **Manual + behavior:** ручной набор с дополнительными поведенческими статистиками (92 признака).
- **Auto:** генерация сочетаний **сущность × окно × агрегат**. Сущности: user, item, genre, user–genre; окна: вся история, 3, 7, 14, 30, 60 и 120 дней. Агрегаты: count, nunique, sum/mean/std по длительности, mean/std по проценту просмотра, давность последнего события, доля жанра в истории пользователя. Всего 232 признака вместе с жанром.
- **Auto_topK:** признаки ранжируются по `CatBoost.get_feature_importance()` модели Auto_all, затем оцениваются варианты K=8,16,32,64,96. Важно: важность извлекается из модели, обученной на train; число K выбирается по validation.

Все CatBoost обучаются с одинаковыми основными настройками: 200 итераций, depth=6, learning rate=0.07, L2=5. Измеряется время обучения и генерации признаков.

## Результаты: основной расширенный эксперимент (seed 2026)

| Модель | Число признаков | Validation NDCG@10 | Test NDCG@10 | Test ROC-AUC | Test LogLoss |
|---|---:|---:|---:|---:|---:|
| Popularity | 1 | 0.691903 | 0.665320 | 0.857447 | 0.171243 |
| Manual | 17 | 0.724552 | 0.712939 | 0.880403 | 0.153275 |
| Manual + behavior | 92 | 0.723487 | **0.714604** | 0.881008 | 0.154386 |
| Auto_all | 232 | **0.724742** | 0.714377 | **0.882070** | 0.153878 |

`Auto_all` выбран среди автоматических вариантов по validation NDCG@10. Его прирост к Manual на test составляет **+0.001438 NDCG@10**. Парный bootstrap по **2 774** пользователям (1 500 повторов) дал **95% интервал [-0.002407, 0.005584]**. Интервал включает ноль: статистически убедительного превосходства Auto над Manual не обнаружено.

Важный нюанс: Manual + behavior имеет максимальный test NDCG в таблице, но его выбор **по test** был бы некорректным. Поэтому этот результат рассматривается как дополнительное наблюдение, а не как основание переопределить победителя.

### Стоимость

Генерация признаков по четырём срезам заняла около **26.7 секунд** (3.72, 6.61, 7.16, 9.19 с). Обучение Manual — около **22.1 с**, Auto_all — **49.7 с**. Это измерения конкретного запуска Colab CPU, а не универсальные бенчмарки.

### Дополнительные эксперименты

В `experiments/` сохранены первоначальная выборка (`seed 42`), репликация (`seed 123`) и исследование расширенных признаков. В `results/` есть исходные CSV и графики исследования бюджета признаков, абляции временных окон и bootstrap. Эти эксперименты были разведочными; поскольку их test уже анализировался, они не считаются независимым подтверждением гипотез, сформулированных позднее.

## Дополнительный исследовательский этап: автоматический поиск семейств и сложные кандидаты (seed 4049)

Это **отдельный запуск на другой выборке пользователей**. Его абсолютные значения нельзя напрямую сравнивать с seed 2026 как парное сравнение.

| Модель | Validation NDCG@10 | Test NDCG@10 |
|---|---:|---:|
| Popularity | 0.669452 | 0.664845 |
| Manual | 0.712488 | 0.728725 |
| Manual + behavior | 0.714376 | 0.728283 |
| Auto_top64 | **0.716346** | **0.729137** |
| FamilySearch | 0.714972 | 0.726470 |

`Auto_top64` выбран по validation; test-разница относительно Manual составляет **+0.000412 NDCG@10**. Парный bootstrap (2 740 пользователей) дал 95%-й интервал **[-0.003411, 0.004148]**, который включает ноль. Следовательно, подтверждённого преимущества нет.

**Feature-family search:** жадный алгоритм пробовал семейства `counts`, `behavior`, `recency`, `relative_share` и принимал очередное семейство при приросте validation NDCG@10 не менее 0.0005. Было принято только `counts` (57 признаков, включая категориальный жанр). Поиск семейств проиграл выбору отдельных top-64 признаков на test, что демонстрирует ограничение грубого группового отбора.

**Более сложные кандидаты:** отрицательные объекты сэмплировались с весами, пропорциональными популярности в доступной прошлой истории. Это отдельный протокол оценки, а не эквивалент настоящих экспозиций.

| Модель | Hard-negative test NDCG@10 |
|---|---:|
| Popularity | 0.340534 |
| Manual | 0.407430 |
| Manual + behavior | **0.408162** |
| FamilySearch | 0.405954 |

**Вычислительные затраты, seed 4049:** обучение Manual ~21.66 с, Manual + behavior ~33.87 с, Auto_all ~54.34 с, Auto_top64 ~29.69 с; генерация признаков для четырёх срезов ~24.64 с. Значения измерены на конкретном Colab CPU.

**Методологические оговорки:** генерация кандидатов для оценивания зависит от будущих положительных событий, метки отрицательных примеров синтетические, `last_watch_dt` не восстанавливает полный журнал событий. Последовательные итерации исследования и просмотр test ограничивают строгость окончательной проверки. В отчёте не заявляется причинное или статистически значимое превосходство.

Данные этапа: `results/*seed4049.csv`, код и сохранённые выводы: `notebooks/AutoFeatureRec_KION_stronger_research.ipynb`. Оригинальные CSV и JSON из `AutoFeatureRec_extended_results.zip` сохранены в `results/` с префиксом `seed4049_`. Ранее восстановленные из ноутбука таблицы оставлены для удобства сопоставления.

## Интерпретация

1. Автоматические исторические агрегаты дают качество, близкое к сильному ручному baseline, без устойчивого статистически подтверждённого выигрыша.
2. Более богатые признаки не гарантируют роста NDCG: добавление статистик поведения улучшает отдельные показатели, но эффект зависит от состава набора.
3. Полный автоматический набор дороже ручного по времени обучения и размерности. При выборе подхода важен баланс качества, вычислительной стоимости и интерпретируемости.
4. Ключевой вклад исследования — **контролируемое сравнение способа конструирования признаков**, а не демонстрация новой архитектуры рекомендательной модели.

## Как воспроизвести

1. Откройте `notebooks/AutoFeatureRec_KION_stronger_research.ipynb` в Google Colab, выберите CPU (это наиболее полный исследовательский запуск). Для воспроизведения seed 2026 используйте `notebooks/AutoFeatureRec_KION_final_research.ipynb`.
2. Выполните ячейки по порядку (`Runtime → Run all`). Первая вычислительная ячейка устанавливает `catboost` и `pyarrow`; данные загружаются из открытого репозитория KION.
3. Параметры последнего ноутбука: `SEED=4049` (предыдущий основной запуск: `SEED=2026`), `N_USERS=15000`, `NEG_PER_POS=15`, `WINDOWS=[3,7,14,30,60,120]`.
4. Выходные файлы формируются в `/content/autofeaturerec_final_2026` (название каталога сохранено из ранней версии даже для seed 4049): `validation_metrics.csv`, `test_metrics.csv`, `feature_importance.csv`, `importance_by_family.csv`, `bootstrap.csv`, `config.json`.
5. Локально при необходимости установите зависимости из `requirements.txt` и замените Colab-путь `/content/` на подходящий локальный каталог.

**Воспроизводимость:** источник данных скачивается извне; его доступность и неизменность необходимо проверять. Версии библиотек в `requirements.txt` заданы минимальными ограничениями, поэтому численные результаты могут незначительно отличаться в другой среде. Текущий ноутбук проверен по сохранённым выводам Colab, но отдельный полный запуск при подготовке этого архива не выполнялся.

## Ограничения и дальнейшая работа

- Датасет не содержит полноценного журнала экспозиций/кликов, а время взаимодействия представлено `last_watch_dt`.
- Отрицательные объекты сэмплированы; offline NDCG не переносится напрямую на ранжирование всего каталога.
- Пользователи с положительными событиями в будущем и будущие положительные объекты участвуют в построении evaluation-кандидатов; это упрощает задачу относительно production serving.
- Пользовательская история короткая (в среднем 5.62 записи на выбранного пользователя), что ограничивает персонализацию.
- Пространство генерации агрегатов ограничено заранее заданными сущностями и операциями; это **не** агентный поиск произвольных SQL-признаков.
- Репликации на разных seed меняют пользовательскую выборку; сравнение абсолютных значений между seed не эквивалентно сравнению моделей на одинаковом test.
- Для более строгой внешней проверки стоит заранее зафиксировать конфигурацию и провести оценку на новом, неиспользованном наборе пользователей и/или более реалистичных кандидатах.
